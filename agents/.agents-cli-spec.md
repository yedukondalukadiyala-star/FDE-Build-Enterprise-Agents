# Agent Spec: `bq-agent`

## Overview
`bq-agent` is a standalone, read-only ADK specialist agent that answers *"Have we seen this software problem before, and how was it fixed?"* by performing semantic vector search over pre-populated engineering incidents in BigQuery (`code_assist_bugs.known_bugs` in `us-central1`). It exposes an externally reachable A2A interface on GKE Autopilot so peer callers can query it over the network without caller-specific coupling.

### Architecture Choice
- **Chosen — Single `LlmAgent` + single `FunctionTool` (`find_similar_bugs`):** Minimal latency, deterministic single-step retrieval, clean A2A card with a single semantic-search skill.
- **Rejected — Multi-agent workflow (query rewriter + retriever + ranker):** Extra LLM hops and latency with no accuracy gain for a 75-row `VECTOR_SEARCH` table (`top_k=3`).

## Language
`python` (ADK Python via `agents-cli`, template `adk_python`).

## Model & Configuration
- **LLM:** `gemini-3.5-flash`, read from `MODEL` environment variable (never hardcoded in Python code), served via Vertex AI (`GOOGLE_GENAI_USE_VERTEXAI=True`, `GOOGLE_CLOUD_LOCATION=global`).
- **Embeddings:** `text-embedding-004` (768 dimensions), called via `google-genai` in the BigQuery table's region (`BQ_LOCATION=us-central1`).
- **BigQuery Target:** Read from env vars with defaults matching the pre-populated table:
  - `GOOGLE_CLOUD_PROJECT`: `qwiklabs-gcp-01-fe4a20503c71`
  - `BQ_DATASET`: `code_assist_bugs`
  - `BQ_TABLE`: `known_bugs`
  - `BQ_LOCATION`: `us-central1`
  - `EMBEDDING_MODEL`: `text-embedding-004`

## Example Use Cases
1. **Matching known incident:**
   - *Input:* `"FastAPI returns a 500 on startup after a dependency bump."` (or any symptom/stack trace matching a row in `code_assist_bugs.known_bugs`)
   - *Expected Output:* Concise summary of matching incident(s), explicitly citing `bug_id` (e.g., `BUG-10XX`) and stating the concrete `resolution` from the table.
2. **Unrelated problem / no relevant match:**
   - *Input:* `"How do I bake sourdough bread at high altitude?"` or a bug in an unrelated system with no relevant match in the table.
   - *Expected Output:* Clearly states that no relevant past incidents were found in the internal bug database; never fabricates bug IDs or fixes.
3. **Empty result / transient backend failure:**
   - *Input:* Any problem query while BigQuery yields zero rows or Vertex AI / BigQuery is temporarily unreachable.
   - *Expected Output:* `find_similar_bugs` catches exceptions and returns a clear `"No similar bugs found."` or graceful degradation message instead of raising; the agent reports unavailability cleanly.

## Tools Required
### `find_similar_bugs(query: str) -> str`
- **Purpose:** Embeds a free-text software problem description and retrieves the 3 closest historical incidents from BigQuery.
- **Retrieval Steps:**
  1. Embed `query` using `text-embedding-004` (768-dim) via `google.genai.Client(vertexai=True, project=PROJECT_ID, location=BQ_LOCATION)`.
  2. Execute a read-only parameterized BigQuery `VECTOR_SEARCH` query in `BQ_LOCATION` (`us-central1`) over `description_embedding` on `` `PROJECT.code_assist_bugs.known_bugs` `` with `distance_type => 'COSINE'` and `top_k => 3`, passing the query vector as `bigquery.ArrayQueryParameter("query_embedding", "FLOAT64", vector)` and ordering by `distance ASC`.
- **Output:** Formatted string containing `bug_id`, `title`, `description`, `resolution`, and cosine `distance` for each match; `"No similar bugs found."` when no rows are returned; or a graceful service-unavailable message if embedding generation or BigQuery fails (never raises unhandled exceptions).
- **Authentication:** Application Default Credentials (ADC) — developer identity locally, Workload Identity (`bq-agent-app@<project>.iam.gserviceaccount.com`) on GKE. No service account key files.

## A2A Interface
- Built on the `agents-cli` scaffolded FastAPI + A2A surface (`/a2a/app` and `/a2a/app/.well-known/agent-card.json`, with v0.3 + v1.0 compatibility).
- Advertises a **single `AgentSkill`** describing semantic search of the internal bug database, including representative `examples` (e.g., `"FastAPI returns a 500 on startup after a dependency bump."`).
- Advertises the **externally reachable** GKE LoadBalancer URL (`http://<EXTERNAL_IP>:8080/a2a/app`) via `APP_URL`.

## Runtime, Credentials & Deployment
- **Target:** GKE Autopilot (`--deployment-target gke`, `--region us-central1`, `--session-type in_memory`, `--cicd-runner skip`).
- **Service Account (`bq-agent-app`):** Bound via GKE Workload Identity; Terraform `app_sa_roles` includes `roles/bigquery.jobUser` and `roles/bigquery.dataViewer` (in addition to `roles/aiplatform.user`, logging, and trace roles).
- **External Reachability:** `kubernetes_service_v1.app` configured as an **external** `LoadBalancer` (removing the default `"cloud.google.com/load-balancer-type" = "Internal"` annotation) so remote A2A clients can reach the agent card and JSON-RPC endpoint over the network.

## Constraints & Safety Rules
- **Strictly read-only BigQuery access:** Never create, seed, update, delete, or DDL-alter `code_assist_bugs.known_bugs`.
- **Strict grounding:** Only report incidents, `bug_id`s, and `resolution`s returned by `find_similar_bugs`. Never invent bug IDs, symptoms, or fixes. Discard retrieved rows whose content/distance is unrelated to the user's query.
- **No hardcoded model or credentials:** Read `MODEL` from configuration/environment and authenticate exclusively via ADC / Workload Identity.

## Success Criteria
1. **Unit tests pass (`uv run pytest tests/unit`):** Tests cover `find_similar_bugs` embedding + parameterized `VECTOR_SEARCH` wiring, ascending cosine-distance formatting, empty-table `"No similar bugs found"` handling, graceful error handling on embedding/BigQuery exceptions, and single-skill A2A `AgentCard` configuration.
2. **Agent evaluation passes (`agents-cli eval run`):**
   - `final_response_quality` ≥ `0.8`
   - `hallucination` ≥ `0.8`
   - Known incidents in `code_assist_bugs.known_bugs` return the matching `bug_id` and `resolution`; unrelated queries report no relevant incidents without fabrication.
3. **GKE A2A verification:** Deployed to GKE in `us-central1` with an external LoadBalancer IP; `GET http://<EXTERNAL_IP>:8080/a2a/app/.well-known/agent-card.json` returns a 200 JSON card advertising `http://<EXTERNAL_IP>:8080/a2a/app` with 1 skill + example query, and live A2A queries succeed end-to-end.
